# 몸무게 기록 앱 설계

- 작성일: 2026-10-12
- 상태: 구현 완료, 2026-10-12 구현 후 변경 사항 반영
- 동작이 이 문서와 다르면 코드와 테스트(`src/**/*.test.ts(x)`)가 기준이다.

## 1. 목적과 범위

### 목적
본인 혼자 스마트폰으로 매일 체중을 기록하고, 목표 대비 진행 상황과 추세를 한눈에 확인한다.

### 사용자가 정한 요구사항
- 개인 1인 사용, 주 사용 기기는 스마트폰
- 기록 항목: 날짜, 체중, 메모
- 목표 체중 설정
- 추세 및 비교
  - 기간 대비 변화 (지난주·지난달 대비)
  - 기간 평균 비교 (이번 주 vs 지난주, 이번 달 vs 지난달)
  - 7일 이동평균 추세선
  - 시작점 대비 변화, 목표 대비 진행률
- 데이터는 기기 내에만 저장하고, 파일로 백업(내보내기/가져오기)
- 구현 방식: PWA

### 가정 (사용자가 별도 이의 없음)
- 하루 1개 기록. 같은 날 다시 저장하면 덮어쓴다.
- 단위는 kg, 소수점 한 자리.
- UI 언어는 한국어.

### 성공 기준
- 앱을 열고 10초 안에 오늘 체중 입력을 마칠 수 있다.
- 홈 화면 하나에서 현재 체중, 목표 진행률, 지난주·지난달 대비 변화, 7일 평균 비교를 볼 수 있다.
- 인터넷 연결 없이 실행·기록할 수 있다.
- 백업 파일로 기록 전체를 다른 기기/브라우저에 복원할 수 있다.

### 범위 제외
- 로그인, 클라우드 동기화, 다중 사용자
- 체지방률 등 체중 외 수치
- 알림/리마인더
- 다크 모드 수동 토글 (시스템 설정 추종만 지원)
- 홈 카드의 기준 날짜 전환 (목표 진행·비교는 항상 가장 최근 기록 기준)
- kg 외 단위

## 2. 화면 구성

하단 탭 3개: **홈**, **그래프**, **기록·설정**.

### 2.1 홈 (기록 + 요약)
- 상단 입력 영역
  - 날짜: 기본값 오늘. 날짜 선택기, 날짜 양옆 ‹ › 버튼, 또는 입력 카드를 좌우로 밀어 하루씩 이동(오른쪽으로 밀면 전날). 미래 날짜 불가.
    - 밀기는 가로 50px 이상이고 세로 움직임의 1.5배 이상일 때만 인정(세로 스크롤과 구분). 저장하지 않은 입력값은 날짜를 바꾸면 사라진다.
  - 체중 입력: 숫자 키패드(`inputmode="decimal"`). 선택한 날짜에 기록이 있을 때만 그 값을 채운다. 기록이 없으면 비워 두고 다른 날짜의 값을 안내 글자로도 보여 주지 않는다.
  - 메모 입력(선택), 저장 버튼.
- 목표 진행 영역
  - 현재 체중, 목표 체중, 목표까지 남은 양, 진행률(%)과 진행 막대.
  - 목표가 없으면 "목표를 설정해 보세요" 링크(설정 화면으로 이동).
- 비교 영역
  - 지난주 대비, 지난달 대비 (증감 방향과 비교한 날짜 표시). 규칙은 3.4.
  - 이번 주 평균(괄호에 지난주 평균).
- 백업 경고 배너 (조건은 4.2 참조).

### 2.2 그래프
- 기간 선택: 1개월 / 3개월 / 6개월 / 1년 / 전체. 기본값 3개월.
- 차트: 날짜별 체중(점), 7일 이동평균(선), 목표 체중(점선).
- 선택 기간 요약: 시작→끝 변화량, 최저, 최고, 평균.
- 평균 비교표: 주간 / 월간 / 월요일 전환.
  - 주간·월간: 최근 8주 또는 최근 6개월의 평균, 최저, 최고, 직전 구간 평균 대비 증감.
  - 월요일: 오늘(또는 그 이전) 가장 가까운 월요일부터 최근 8번의 월요일에 기록한 체중 그대로와 직전 월요일 대비 증감. 기록이 없는 월요일은 "–"이고 빠진 주를 건너뛰어 비교하지 않는다.
- 그래프 화면은 처음 열 때 불러온다(지연 로딩). 오프라인 캐시에 포함된다.

### 2.4 레이아웃과 스타일
- 라벤더 바탕, 흰 카드, 목표 카드에만 그라디언트. 숫자는 Outfit(앱에 포함), 한글은 기기 기본 글꼴.
- 시스템 설정을 따르는 다크 모드.
- 폭 600px 이상(폴드 펼친 화면 등)에서는 두 칸: 홈은 입력 | 목표·비교, 그래프는 넓은 차트 아래 요약 | 평균표, 기록·설정은 목록 | 설정.

### 2.3 기록·설정
- 기록 목록: 최신순. 날짜, 체중, 전일 기록 대비 증감, 메모. 항목을 눌러 수정/삭제.
- 설정
  - 목표 체중
  - 시작 체중/시작일 (기본값: 첫 기록. 직접 변경 가능)
  - 백업 내보내기 / 가져오기
  - 마지막 백업 일시 표시

## 3. 구조와 데이터

### 3.1 기술 구성
| 용도 | 선택 |
|---|---|
| 빌드/개발 | Vite + React + TypeScript |
| 저장소 | IndexedDB (`idb` 래퍼) |
| 차트 | Recharts |
| PWA | `vite-plugin-pwa` (오프라인 캐시, manifest, 홈 화면 아이콘) |
| 테스트 | Vitest, Testing Library, `fake-indexeddb` |
| 배포 | GitHub Pages + GitHub Actions |

### 3.2 데이터 모델
```ts
type Entry = {
  date: string;      // "YYYY-MM-DD", 기기 로컬 시간대 기준. 기본 키.
  weightKg: number;  // 20.0 ~ 300.0, 소수점 한 자리
  memo?: string;     // 최대 200자
  updatedAt: number; // epoch ms
};

type Settings = {
  goalKg?: number;
  startDate?: string; // 미설정 시 첫 기록 날짜
  startKg?: number;   // 미설정 시 첫 기록 체중
  lastBackupAt?: number;
  firstUseAt?: number; // 백업 경고 계산용
};
```
- IndexedDB 스토어: `entries` (keyPath `date`), `settings` (단일 레코드).

### 3.3 모듈 구성
```
src/
  db/storage.ts    Entry/Settings 저장·조회·삭제. IndexedDB 접근은 여기서만.
  stats/stats.ts   순수 함수: 이동평균, 기간 대비 변화, 주/월 평균, 진행률, 기간 요약.
  backup/backup.ts JSON 내보내기 생성, 가져오기 검증, 병합/교체 결과 계산.
  ui/              Home, Chart, History, Settings 화면과 공용 컴포넌트.
```
- `stats.ts`와 `backup.ts`의 계산 부분은 IndexedDB·DOM에 의존하지 않는 순수 함수로 둔다.

### 3.4 계산 규칙
- **기준 기록(현재 체중)**: 날짜가 가장 늦은 기록.
- **지난주 대비**: 기준 기록과 정확히 7일 전(같은 요일) 기록의 차이.
- **지난달 대비**: 기준 기록과 지난달 같은 날 기록의 차이. 그 날이 없으면 지난달 마지막 날(3/31 → 2/28, 윤년 2/29, 5/31 → 4/30).
- 두 비교 모두 비교할 날에 기록이 없으면 "–" (비슷한 날로 대신하지 않는다).
- **7일 이동평균**: 날짜 D에 대해 [D−6, D] 구간에 있는 기록들의 평균. 기록이 없는 날은 제외. 구간 내 기록이 0개면 값 없음.
- **이번 주/지난주 평균 (홈)**: 기준 기록 날짜가 속한 월~일 주와 그 직전 주의 기록 평균. 해당 주에 기록이 없으면 "–".
- **주 평균 / 월 평균 (그래프)**: 주는 월요일 시작~일요일, 월은 달력 월. 기록이 없는 구간은 표에서 "–".
- **시작 체중**: 설정한 시작 체중. 비어 있고 시작일만 있으면 시작일 이후 첫 기록의 체중, 둘 다 없으면 첫 기록.
- **시작점 대비 변화**: 현재 − 시작 체중.
- **진행률**: (시작 − 현재) / (시작 − 목표) × 100, 0~100으로 제한. 시작 = 목표이면 100%. 감량·증량 목표 모두 같은 식.
- 표시 값은 소수점 한 자리로 반올림한다. 계산 중간에는 반올림하지 않는다.

## 4. 오류 처리와 데이터 보호

### 4.1 입력 검증
- 체중: 20.0~300.0, 소수점 한 자리까지. 쉼표는 점으로 변환. 범위 밖이거나 숫자가 아니면 저장 불가와 함께 오류 문구 표시.
- 직전 기록 대비 3kg 넘게 차이 나면 "입력값을 확인해 주세요" 경고. 저장은 막지 않는다.
- 미래 날짜 선택 불가.
- 메모 최대 200자.

### 4.2 데이터 유실 방지
- 첫 실행 시 `navigator.storage.persist()` 요청.
- 백업 경고 배너: `lastBackupAt`(없으면 `firstUseAt`)로부터 30일이 지났고 기록이 1개 이상이면 홈에 표시. 배너에서 바로 내보내기 가능.
- 내보내기 파일명 `weight-backup-YYYY-MM-DD.json`, 형식:
  ```json
  { "version": 1, "exportedAt": "ISO 8601", "entries": [Entry], "settings": Settings }
  ```
  내보내기 시 파일의 `settings.lastBackupAt`에 내보낸 시각을 넣고, 기기의 `lastBackupAt`도 갱신.
- 가져오기
  1. 전체 형식 검증 (JSON 파싱, `version === 1`, 각 Entry 필드·범위). 하나라도 실패하면 아무것도 변경하지 않고 오류 표시.
  2. 사용자가 **병합**(같은 날짜는 파일 값 우선, 설정은 파일 값 우선. 단 `lastBackupAt`은 더 최근 값, `firstUseAt`은 더 이른 값) 또는 **전체 교체**를 선택. 교체는 추가 확인.
  3. 단일 트랜잭션으로 반영.
- 기록 삭제는 확인 대화상자 후 실행.

### 4.3 빈 상태·경계 상황
- 기록 0개: 홈에 입력 영역과 안내 문구만 표시. 그래프 화면은 안내 문구.
- 기록 1개: 비교 수치 "–".
- 목표 미설정: 진행률 대신 설정 유도 링크. 그래프의 목표선 생략.
- IndexedDB 사용 불가: 전체 화면에 "이 브라우저 모드에서는 기록을 저장할 수 없습니다" 안내.
- 저장·삭제·설정 저장·가져오기 실패: 해당 위치에 오류 문구.
- 저장 구조 업그레이드: 다른 창의 새 버전이 업그레이드하면 이 창은 연결을 닫고 "새 버전이 준비됐어요" 안내로 바뀐다. 이 창의 업그레이드가 예전 버전 창 때문에 막히면 "다른 창을 닫아 주세요" 안내.

## 5. 테스트

- **단위 (Vitest)**
  - `stats.ts`: 이동평균(빠진 날 포함), 같은 날 비교(정확한 날, 월말 맞춤, 기록 없음), 주/월 평균·최저·최고 경계(월요일 시작, 월말·연말), 월요일 목록, 진행률(감량·증량·초과·시작=목표), 기간 요약.
  - `backup.ts`: 정상 파일, 깨진 JSON, 버전 불일치, 필드 누락·범위 위반, 병합/교체 결과.
  - `storage.ts` (`fake-indexeddb`): 저장, 같은 날짜 덮어쓰기, 삭제, 설정 저장, 다른 연결의 업그레이드 시 닫힘.
- **컴포넌트 (Testing Library)**: 홈에서 입력 → 저장 → 요약 갱신, 입력 검증 오류·경고 표시.
- **수동 확인**: 실제 폰에서 홈 화면 추가, 오프라인 실행, 내보내기 → 다른 브라우저에서 가져오기.
